## What task analysis is for

Task analysis answers the question: **what, exactly, must the learner be able to do, and what does that performance consist of?** It turns a goal ("nurses will administer medications safely in the new system") into a map of the knowledge, skills, and decisions the goal requires. That map determines the objectives (Module 4), the sequence and strategies (Module 6), and the assessments. Without it, designers teach what they happen to know rather than what the performance requires.

Dick and Carey call this "instructional analysis" and split it into two questions: what type of learning is the goal, and what subordinate skills does it require?

## Step 1: Classify the goal

Gagné's taxonomy of learning outcomes is the standard classification. The type of outcome determines the analysis method and, later, the instructional conditions.

| Outcome type | What the learner does | Example | Analysis method |
| --- | --- | --- | --- |
| **Verbal information** | States, recalls, describes | Name the five rights of medication administration | Cluster analysis: group the information into logical sets |
| **Intellectual skills** | Discriminates, classifies, applies rules, solves problems | Decide whether a scanned wristband matches the order | Hierarchical analysis: identify subordinate skills |
| **Cognitive strategies** | Manages own thinking and learning | Choose a checking strategy under time pressure | Hierarchical analysis plus the intellectual skills it governs |
| **Motor skills** | Performs a physical procedure | Scan a wristband with a handheld scanner | Procedural analysis: list the steps in order |
| **Attitudes** | Chooses to act in a certain way | Choose to scan every time, even when the scanner is slow | Analyze the behavior chosen and the intellectual skills and information that support it |

Most real goals combine types. A procedural task includes decisions (intellectual skills) at branch points and requires information at several steps. Classify the overall goal, then classify each component as you decompose it.

## Step 2: Decompose the goal

### Procedural analysis

For goals that are performed as a sequence of steps, list the steps in order, with the decisions at each branch. Use a flowchart or a numbered list with sub-steps. For each step, note the inputs (what the learner needs to see or know), the action, and the result that signals the step is complete.

Example fragment, medication administration:

1. Verify patient identity by scanning the wristband.
   - 1.1 If the scan succeeds and matches, proceed to step 2.
   - 1.2 If the scan fails to read, re-scan; after two failures, use the manual override procedure (step 1.3).
   - 1.3 Manual override: enter the medical record number, confirm two identifiers verbally, document the override reason.
2. Scan the medication barcode.
   - 2.1 If a mismatch alert appears, stop; do not administer; follow the alert workflow.

Procedural analysis reveals branch points, which are where errors happen and where practice should concentrate. It also exposes steps that the expert performs automatically and would never think to teach.

### Hierarchical analysis

For intellectual skills, start with the goal and ask repeatedly: **"What must the learner already be able to do in order to learn this?"** Each answer is a subordinate skill; place it below the goal and ask the question again. Stop when you reach the entry skills the learners already have (from your learner analysis). The result is a hierarchy in which lower skills must be learned before higher ones.

Example: to *decide whether a mismatch alert requires stopping*, the learner must be able to *interpret the alert type*, which requires *distinguishing wrong-patient, wrong-drug, and wrong-time alerts*, which requires *reading the alert display*, which is an entry skill.

### Cluster analysis

For verbal information, group the items into meaningful clusters (by function, by location, by time) so that they can be taught and remembered as sets. Clusters often map onto job aids.

### Cognitive task analysis

Experts make decisions they cannot easily articulate. Cognitive task analysis (CTA) uses structured interviews, think-aloud protocols, and critical-incident recall to surface the cues experts attend to, the decisions they make, and the errors novices make at the same points. CTA is expensive and is reserved for complex, high-stakes tasks, but even a light version (asking an expert to narrate a recent difficult case and probing at each decision) improves any analysis. Clark and colleagues summarize the evidence that instruction based on CTA outperforms instruction based on expert self-report.

## Step 3: Identify entry skills

Draw a line across the bottom of your hierarchy. Everything below it is assumed; everything above it is taught. Where you draw the line comes from the learner analysis. If learners vary widely, you may need two lines and two paths.

## Step 4: Check the analysis

- **Completeness.** Could a novice perform the goal using only what is in the analysis? Have an expert and a novice review it.
- **Level of detail.** Steps should be small enough to teach and assess, large enough to be meaningful. "Click OK" is too small; "administer medication" is too large.
- **Accuracy.** Observe the task performed. Analyses built from documentation alone miss workarounds and tacit steps.
- **Decisions and errors.** Every branch point should be explicit, and the common errors at each should be noted; they become practice items and assessment distractors.

## Representing the analysis

Use whichever representation fits the outcome type:

- Flowchart for procedures with branches.
- Tree diagram for hierarchies.
- Table with columns for step, cues, action, decision, common errors, and outcome type.
- Outline for clusters of information.

Whatever the form, number every element so objectives can reference them in Module 4.

## Common mistakes

- Listing topics ("the medication module") instead of performances.
- Stopping decomposition too early, so that the first objective is unteachable in one lesson.
- Omitting decisions and error handling; procedures are taught as the happy path and fail in practice.
- Analyzing from documentation without observing or interviewing performers.
- Ignoring the attitudes component; many performance failures are choices, not skill gaps.
