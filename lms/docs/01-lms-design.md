# LMS Design: David Awoyemi Learning Studio

This document is the design specification for the learning management system (LMS) that hosts David Awoyemi's online instructional courses. It records the platform decision, the architecture, the branding, the course template standard every course follows, and the quality checklist used before a course is published.

## 1. Purpose and goals

The LMS exists to:

1. Deliver self-paced and cohort-based online courses in instructional technology, AI literacy, and arts-integrated learning to teachers, graduate students, and workforce learners.
2. Serve as a living teaching portfolio: every course is evidence of instructional design practice.
3. Support research: pre/post surveys, completion data, and artifact galleries are built into the course template so studies (such as the 2025 art-integrated GenAI literacy pilot) can run on the platform.
4. Remain portable. Course content is authored in a platform-neutral source format and exported as IMS Common Cartridge, so courses can move to Canvas, Blackboard, or another Moodle without rework.

## 2. Platform decision

**Chosen: Moodle 4.5 LTS, self-hosted with Docker.**

| Option | Verdict | Reasons |
| --- | --- | --- |
| Moodle (self-hosted) | Chosen | Open source, mature gradebook, quizzes, forums, SCORM and H5P support, imports Common Cartridge, large plugin ecosystem, one-command Docker install, well documented, free |
| Canvas LMS (open-source self-host) | Rejected | Excellent UI but self-hosting requires Ruby, PostgreSQL, Redis, and several services; heavy to maintain for one person |
| Open edX | Rejected | Built for MOOC scale; operationally complex for a small catalog |
| MoodleCloud (hosted) | Fallback | Same Moodle without server maintenance; use if running a server proves too costly in time. Courses import unchanged |
| Static site "learning hub" | Rejected for now | Fits the existing GitHub Pages site but has no accounts, gradebook, or forums; could be added later as a public course catalog that links into Moodle |

## 3. Architecture

```
Learners / Instructor (browser)
        |
     HTTPS (Caddy reverse proxy, automatic certificates)
        |
   Moodle 4.5 (PHP/Apache container)  <---->  MariaDB 11 (container)
        |
   moodledata volume (uploads, backups, cache)
        |
   Nightly backups: database dump + moodledata archive -> off-server storage

Authoring pipeline (this repository):
   lms/courses/<slug>/  (Markdown + JSON)  --build_cartridge.py-->  lms/dist/<slug>.imscc  --Restore-->  Moodle course
                                                              \-->  lms/dist/preview/<slug>/index.html (browser review)
```

Hosting target: a small virtual private server (2 vCPU, 4 GB RAM, 40 GB disk) is enough for a few hundred learners. A domain such as `learn.<your-domain>` points at the server. See `02-moodle-setup.md`.

## 4. Roles and permissions

| Role | Who | Can |
| --- | --- | --- |
| Site administrator | David Awoyemi | Everything: install plugins, theme, users, backups |
| Manager | A trusted co-instructor or research assistant | Create courses, enroll users, view all reports |
| Teacher | Course instructors and co-designers | Edit and grade within assigned courses |
| Non-editing teacher | Teaching assistants, peer reviewers | Grade and post, not edit content |
| Student | Enrolled learners | Participate |
| Guest | Public | View course descriptions in the catalog; no access to activities |

Enrollment methods: self-enrollment with an enrollment key for cohorts; manual enrollment for research participants; guest access only on the catalog page.

## 7. Course template standard

Every course follows the same structure so learners always know where they are and so courses can be compared in research.

**Course shell**

- Module 0: Welcome and orientation (welcome page with video, how the course works, tools and setup, responsible AI use, introduction forum, pre-course self-assessment).
- Content modules: each with an introduction page, lessons, and a module reflection.
- Final module: applied project, peer feedback, post-course self-assessment, completion page.

**Lesson pattern (seven steps)**

1. Watch: short introductory video and objectives.
2. Learn: key ideas.
3. Do: step-by-step activity.
4. Create: a shareable artifact.
5. Share: post the artifact and a rationale (75 words) to the lesson gallery forum.
6. Check: a 5 to 10 question knowledge check with feedback on every option.
7. Reflect: two or three prompts carried into the module reflection.

**Assessment standard**

- Competency- or objective-based; criterion-referenced.
- Every rubric is analytic with four levels and point ranges.
- Knowledge checks allow unlimited attempts with best score kept; every distractor has feedback.
- Pre- and post-course self-assessments use identical items so growth can be measured.

**Responsible AI standard**

- Every course states what AI use is allowed, what must be disclosed, and what is prohibited.
- Every AI-assisted artifact carries a one-line credit: tool, version, human contribution.

**Accessibility standard**

- WCAG 2.2 AA for all pages; captions on all video; alt text on all meaningful images; keyboard-operable interactions; real headings.
- Content pages use Atkinson Hyperlegible (designed for legibility) and 4.5:1 contrast.

## 8. Authoring workflow

1. Write or edit course source in `lms/courses/<slug>/` (see `03-course-authoring.md`).
2. Run `python lms/scripts/build_cartridge.py`.
3. Open `lms/dist/preview/<slug>/index.html` and review the entire course in the browser.
4. Import `lms/dist/<slug>.imscc` into Moodle (Course > Restore).
5. Complete the post-import checklist in `02-moodle-setup.md` (convert assignment pages to Assignment activities, record and embed videos, set forum and quiz options, check the gradebook).
6. Run the quality checklist below with a test student account.
7. Publish (make the course visible) and open enrollment.

## 9. Quality checklist before publishing a course

- [ ] Every module has an introduction and every lesson follows the seven-step pattern.
- [ ] Every objective is observable and mapped to at least one activity and one assessment.
- [ ] Every assignment has an analytic rubric and a due date or "self-paced" label.
- [ ] Every quiz question has feedback; quiz settings match the course policy (attempts, grading method).
- [ ] Every video is embedded, plays, and has accurate captions.
- [ ] Every external tool link opens and the free tier still works.
- [ ] Gradebook totals match the weights stated on the welcome page.
- [ ] Course completion criteria are set and the certificate (if any) issues on completion.
- [ ] A test student account can complete Module 0 end to end without instructor help.
- [ ] Responsible-use page and AI credit requirement are present.
- [ ] Accessibility check (Brickfield or the Moodle accessibility toolkit) shows no errors.

## 10. Data, privacy, and research

- Learner data stays on the self-hosted server; enable Moodle's privacy and data-retention policies (Site administration > Users > Privacy and policies).
- Research courses live in the hidden "Research Studies" category, enroll by key only, and link to the IRB-approved consent form before Module 0.
- Export survey and quiz responses from Moodle reports; never store identifiable data outside the LMS.

## 11. Backups and maintenance

- Nightly: database dump and `moodledata` archive copied off-server (see setup guide).
- Weekly: Moodle course backups (automated backups in Site administration).
- Monthly: apply Moodle point releases; review plugin updates.
- Before every upgrade: full backup and a test restore on a local Docker instance.
